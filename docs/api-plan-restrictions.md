# 契約プランによる API の制限

## この文書の位置づけと収集条件

この文書は、カラーミーショップの契約プランによって、使えない API と、使えるが制約が変わる API をまとめる。
公式 OpenAPI の記載と、テスト用ショップでの実測を分けて書く。

公式 OpenAPI は **2026-10-21（Asia/Tokyo）** に取得した [`open_api.json`](https://api.shop-pro.jp/v1/spec/open_api.json)
（41 パス、58 操作）を使った。全文から「プラン」「プレミアム」「401200」を機械的に探し、ショップ情報の応答の
`contract_plan` と `domain_plan` の説明を除いたすべての記載を拾った。

実測は **2026-10-21（Asia/Tokyo）** に、テスト用ショップで行った。テスト用ショップの契約プランは、利用者が管理画面で
確かめたところエコノミーかフリーで、どちらかは決まっていない。ショップ情報 GET の `contract_plan` は `unknown`、
`state` は `unsigned`、`contract_start_date` と `contract_end_date` は `null` で、契約プランは API からは分からない。
プレミアムプランのショップでは、どの API も実測していない。記録したのは HTTP ステータス、エラーのコードとメッセージ、
キーの有無だけで、ID や値は記録しない。

## プランで使えない API

公式 OpenAPI が「カラーミーショップでご契約中のプランがプレミアムのアカウントでのみご利用いただけます。」と
説明している操作は、次の 2 つだけだった。テスト用ショップでは、どちらも `401`（code `401200`「現在契約中のプランでは
ご利用いただけません。」）になった。

| API | ライブラリのメソッド | 使えるプラン | テスト用ショップでの実測 |
| --- | --- | --- | --- |
| `POST /v1/sales`（受注データの作成） | `Client::createSale()` | プレミアム | 空の `sale` を送っても `401200`。body の検証より先にプランが判定される（[受注作成 API の実測記録](api-sale-create-observation.md)） |
| `POST /v1/products/{product_id}/images`（商品画像の登録） | `Client::createProductImage()` | プレミアム | 存在しない商品 ID で、画像ファイルを付けなくても `401200`。入力の検証より先にプランが判定される（[商品応答構造の実測記録](api-product-structure.md#画像-api)） |

使えないプランでは、ライブラリは `401` の `Results\Errors` を返す。どちらも、成功時の応答の形は公式 OpenAPI に
基づいており、実 API では確かめていない。

## 実測でプランの制限を受けなかった API

公式 OpenAPI の 58 操作のうち、上の 2 つ以外は、テスト用ショップで `401200` にならなかった。ほかのプランでは確かめて
いないため、すべてのプランで制限されないとまでは言えない。

- **取得の 26 操作**: 25 操作は `200` だった（テンプレートの 3 操作は、`read_templates` を付けたトークンで確かめた）。
  ショップクーポンの単体（`GET /v1/shop_coupons/{coupon_id}`）は、クーポンがないため存在しない ID で `404` まで確かめた
- **商品、グループ、カテゴリー、顧客、受注の更新系**: これまでの観測記録で成功を確かめている
- **商品画像の削除**（`DELETE /v1/products/{product_id}/images/{position}`、`Client::deleteProductImage()`）: 公式 OpenAPI に
  プランの制限の記載がない。画像の登録が `401200` になる同じショップで、メイン画像とサブ画像の削除はどちらも `204` で
  成功した（[商品応答構造の実測記録](api-product-structure.md#2026-10-21-の追加観測画像の削除)）。画像の登録が使えない
  プランでは、削除した画像を API で戻せない
- **ショップクーポンの作成と削除**（`POST /v1/shop_coupons`、`DELETE /v1/shop_coupons/{coupon_id}`）: 利用不可
  （`status: unavailable`）の検証用クーポンを作ると `201` で、応答の `shop_coupon` を返した。すぐに削除すると `204` で、
  削除後の単体 GET は `404` だった。更新（`PUT`）は、存在しない ID で `404`（code `404100`）まで確かめた。
  **利用者によると、管理画面ではショップクーポンはレギュラープラン以上の機能と表示されているが、API では作成と削除が
  できた。** このライブラリはショップクーポンの API を実装していない
- **テンプレートのページの更新**（`PUT /v1/templates/{template_id}/pages/{page_type}`）: 未利用（`inactive`）のテンプレートの
  `top` ページに、取得した `html` と `css` をそのまま送ると `200` で、内容は変わらず、テンプレートの `update_date` だけが
  新しくなった。このライブラリはテンプレートの API を実装していない
- **受注のキャンセル、メールの送信、決済 URL の作成**: 存在しない受注 ID（`0`）で `404` だった（決済 URL は
  code `404000`、ほかは `404100`）。プランの判定は通っている。成功は、受注を変えるため確かめていない

## プランとは別の条件で使えない API

| 条件 | API | テスト用ショップでの実測 |
| --- | --- | --- |
| 公式の「会員ランク」アプリの契約 | `PUT /v1/customers/{customer_id}/membership`、`DELETE /v1/customers/{customer_id}/membership` | `403`（code `403000`「権限がありません。」）。公式 OpenAPI に「アプリストアで提供している『会員ランク』を利用している場合にのみリクエストできます」とあり、利用者によるとアプリの契約が必須と案内されている。このライブラリは実装していない |
| トークンのスコープ | ショップクーポンの書き込み（`write_shop_coupons`）、テンプレートのすべての操作（`read_templates`、`write_templates`） | これらのスコープがないトークンでは `403` で、本文は空の HTML（`Content-Type: text/html`）だった。`401200` や `403000` のような JSON のエラーは返らなかった。スコープを足したトークンでは通った。ほかのスコープが足りない場合の応答は確かめていない |

## 使えるが、プランによって制約が変わるもの

| 対象 | 公式 OpenAPI の制約 | テスト用ショップでの実測 | ライブラリでの扱い |
| --- | --- | --- | --- |
| 商品の作成・更新の `sales_price` と `members_price`（`ProductCreateInput`、`ProductUpdateInput`） | フリープランでは最低価格が 100 円 | 非公開の検証用商品の `sales_price` に `50` と `99` を送ると、どちらも `200` で保存された（元の値に戻した）。API がこの制約を検証していないのか、テスト用ショップがフリープランではないのかは決められない | 検証しない。API の検証に委ねる |
| バリエーションの更新の `option_price` と `option_members_price`（`VariantUpdateInput`） | フリープランでは最低価格が 100 円 | 確かめていない | 検証しない。API の検証に委ねる |
| テンプレートのページの `html`（`/v1/templates/{template_id}/pages/{page_type}`） | プラチナとプレミアムは最大 120,000 文字、ほかは最大 65,530 文字 | 確かめていない（内容を書き換える必要があるため） | テンプレートの API は実装していない |

## 確かめていないこと

- テスト用ショップの実際の契約プラン（エコノミーかフリーか）
- プレミアムプランのショップで、受注データの作成と商品画像の登録が成功すること
- テスト用ショップ以外のプランで、上の「実測でプランの制限を受けなかった API」が使えること
- 管理画面でレギュラープラン以上と表示されるショップクーポンが、API では作成できた理由
- フリープランのショップで、最低価格を下回る価格を送ったときの応答
- テンプレートの `html` の文字数の上限
