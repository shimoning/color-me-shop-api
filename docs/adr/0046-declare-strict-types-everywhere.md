# ADR 0046: すべての PHP ファイルで strict_types を宣言する

- 状態: 採用
- 決定日: 2026-10-12

## 文脈

`declare(strict_types=1);` を宣言しているファイルと、していないファイルが混ざっていた。src では、`Entities\Entity` や
`Communicator\Request` などの比較的新しいファイルは宣言していたが、Constants、多くの Entity と Service、例外、値オブジェクト、
`Client` は宣言していなかった。tests と `client` スクリプトも同じく混ざっていた。

`strict_types` は、宣言したファイルの中から行う関数・メソッドの呼び出しにだけ効く。宣言のないファイルでは、スカラーの
引数が宣言された型に暗黙に変換される。同じライブラリの中で、ファイルによって型の扱いが変わっていた。利用者のコードから
ライブラリを呼ぶときの扱いは、利用者のファイルの宣言で決まり、ライブラリ側の宣言には左右されない。

## 判断

- **src、tests、examples、`client` スクリプトのすべての PHP ファイルで `declare(strict_types=1);` を宣言する。** ファイルに
  よって型の扱いが変わらないようにする。新しく足すファイルも宣言する。利用者の指定による。出典: `a6b2cab`。
- 規則はテストで守り、宣言のないファイルを検出する。出典: `a6b2cab`。
- 宣言によって暗黙の変換がなくなる呼び出しのうち、利用者の入力を受けるものは、宣言の前と同じ結果になるよう明示的に
  扱う。`Values\Furigana::validate()` は文字列でない値に `false` を返し、`Communicator\RequestOptions` の `authorization`
  は文字列に変換してから扱う。出典: `a6b2cab`。

## 代替案と却下理由

- **src だけに宣言する案**は、ライブラリの動作に関わる範囲に限れる。しかし tests で暗黙の変換に頼った入力を書くと、
  src の型の誤りを見逃しうる。
- **宣言しないファイルに揃える案**は、暗黙の変換で動いていた呼び出しを壊さない。しかし型の誤りが変換に隠れ、
  厳密な型付けの方針に合わない。

## 帰結

ライブラリの中の呼び出しは、どのファイルでも暗黙の型変換をしない。利用者のコードからライブラリを呼ぶときの扱いは
変わらない。
