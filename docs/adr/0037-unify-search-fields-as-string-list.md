# ADR 0037: 一覧取得の検索条件の fields を文字列の配列に揃える

- 状態: 採用
- 決定日: 2026-10-08

## 文脈

一覧取得の検索条件の `fields`（応答のキーを絞り込む指定）は、検索条件によって指定方法が違っていた。

- 商品・在庫・バリエーションの検索条件は、文字列（`'id,name'`）で受け、そのまま送っていた
- 受注の検索条件は、文字列の配列（`['id', 'name']`）で受けていた。0.27.1 で、配列の形式ではなくカンマ区切りで
  送るように直した
- 顧客の検索条件には `fields` がなかった

2026-10-08 に実 API で確かめたところ、次のとおりだった。詳細は
[検索条件のクエリ形式の実測記録](../api-search-query-format-observation.md)にある。出典: `6eff5bc`、`d02e40b`、`9496a07`。

- 商品・在庫・バリエーション・受注の一覧は、カンマ区切りの `fields` で応答のキーを絞り込んだ
- 顧客の一覧と顧客の単体取得も、公式 OpenAPI に記載はないが、カンマ区切りの `fields` で応答のキーを絞り込んだ
- 商品広告の一覧は、`fields` を指定しても HTTP 200 で応答のキーが変わらず、絞り込まなかった（公式 OpenAPI にも `fields` はない）
- 商品広告を除くどの一覧も、`fields[0]=id&fields[1]=name` の配列の形式では、エラーにならずキーを持たない要素を返した

## 判断

- **一覧取得の検索条件の `fields` は、すべて文字列の配列で受け、クエリではカンマ区切りで送る。** 商品・在庫・
  バリエーションの検索条件も、受注と同じ指定方法に揃える。文字列での指定は、生成時に `InvalidFieldException` で
  拒否する。利用者の指定による。出典: `b790912`。
- **顧客の検索条件に `fields` を加える。** 公式 OpenAPI には記載がないが、実 API が受け付けることを確かめた。
  PHPDoc に「公式 OpenAPI との差分」として書く。利用者の指定による。出典: `37f73b9`。
  ADR 0035 の「公式 API にない機能を作らない」は、複数のリクエストを組み合わせて公式 API にない結果を作る機能を
  対象とする。顧客の `fields` は、実 API が 1 回のリクエストで受け付ける指定であり、これに当たらない。
- 商品広告の検索条件には `fields` を加えない。実 API が `fields` で応答を絞り込まないためである。出典: `9496a07`。
- 文字列の `fields` を持つまま直列化した商品・在庫・バリエーションの検索条件は、`unserialize()` で復元できなく
  なる（`TypeError`）。古い形式から変換する処理は加えず、既知の非互換としてテストで固定する。利用者の指定による。
  出典: `b790912`。

## 代替案と却下理由

- **文字列に揃える案**は、商品・在庫・バリエーションの利用者のコードが壊れない。しかし受注の配列での指定が
  壊れる。利用者の指定により、配列に揃える。
- **文字列と文字列の配列の両方を受け付ける案**は、どの利用者のコードも壊れない。しかし `FIELD_TYPES` で 2 つの
  型を許す仕組みが必要になり、指定方法も揃わない。
- **古い直列化データの文字列の `fields` を、復元時に配列に変換する案**は、直列化データの互換を保てる。しかし
  検索条件は送信のたびに作る値で、直列化して保存する使い方は多くないと考え、古い形式のための変換は残さない。

## 帰結

一覧取得の検索条件の `fields` は、すべて同じ指定方法になる。

次の点が変わる。破壊的変更のため、次のマイナーバージョンで行う。

- 商品・在庫・バリエーションの検索条件に `fields` を文字列で渡しているコードは、`InvalidFieldException` になる。
  文字列の配列に書き換える必要がある
- 商品・在庫・バリエーションの検索条件の `toArray()` の `fields` は、文字列から配列になる。送信するクエリ
  （`toArrayRecursive()`）は従来どおりカンマ区切りの文字列である
- 文字列の `fields` を持つまま直列化した、これらの検索条件は復元できない
- 顧客の一覧の `fields` は、公式 OpenAPI にない指定に頼る。実 API が受け付けなくなった場合は、効かなくなる
