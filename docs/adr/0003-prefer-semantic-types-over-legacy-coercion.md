# ADR 0003: 暗黙変換より意味上正しい型を優先する

- 状態: 採用
- 決定日: 2026-09-08

## 文脈

型宣言と値の意味が食い違い、暗黙の型変換によって不正な入力や戻り値の不整合が見えにくく
なっていた。型を正すと、一部の厳密な呼び出し側には互換性への影響が生じる。

## 判断

- OAuth のリダイレクト URI は `AuthRedirectUri|string` と宣言する。非 strict な呼び出し元で
  数値などが文字列化される挙動は PHP の呼び出し規則として残るが、strict な呼び出し元が
  意味的に不正なスカラー値を渡すことまで互換契約とはしない。実装: `6fac6d6`。
  影響評価の出典: `1554aa6`。
- `Sale::getPaymentId()` は文字列へキャストせず `int` を返す。決済方法 ID は数値であり、
  対応するプロパティや他の数値 ID の getter と型を揃えるためである。厳密比較や
  `is_string()` に依存する利用者には破壊的変更となることを受け入れた。出典: `3e4e874`。

## 現在の状態

両方の型契約は現行コードでも維持されており、判断は有効である。当時の「0.6 系だから型を
明確化する」という補助的な理由は、現行が 0.8.0 であるため古い。今後の互換性評価では過去の
バージョン番号を根拠にせず、値の意味、影響範囲、移行方法を個別に判断する。

## 帰結

暗黙変換で既存挙動を再現するより、API の意味とライブラリ内の一貫性に合う型を選ぶ。
互換性を変える場合は、影響を受ける呼び出し方を明示して判断を残す。
