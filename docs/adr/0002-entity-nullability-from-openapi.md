# ADR 0002: Entity の null 許容性を OpenAPI に合わせる

- 状態: 採用
- 決定日: 2026-09-08

## 文脈

API レスポンスに項目がないと、未初期化の型付きプロパティを getter が参照して `Error` に
なる。一方、非 null 許容プロパティを機械的に nullable に変えると、API の型契約を弱める。

## 判断

- レスポンスにない null 許容プロパティは `Entity` 基底クラスで `null` に初期化する。
  個々の Entity に既定値を追加するより追加漏れがなく、方針を一箇所に保てるためである。
  リフレクション結果はクラス単位でキャッシュする。出典: `c0a1ab8`。
- キャッシュや生データなど、アンダースコアで始まる内部プロパティは配列化しない。
  内部実装を Entity の出力契約へ混入させないためである。出典: `c0a1ab8`。
- 全 Entity の契約テストで、getter が未宣言プロパティを参照しないことと、欠損した nullable
  プロパティの getter が `null` を返すことを横断的に固定する。個別テストだけでは同じ種類の
  欠陥の追加を防げないためである。出典: `c0a1ab8`。
- 非 null 許容型は一律に変更せず、公式 OpenAPI が明示する `nullable: true` と PHP 側の型を
  突き合わせる。監査時の仕様では `required` が判断材料にならなかったため、必須性をそこから
  推測しない。仕様更新時は再監査する。出典: `bd6f9c2`。
- 監査で不整合だった `Shop::$hojin`、`Shop::$hojinKana`、
  `Product\Group::$parentGroupId` は nullable にする。`getParentGroupId()` の `?int` 化は
  型上の互換性を変えるが、従来は正当な `null` 応答で構築自体が失敗したため修正を優先した。
  出典: `bd6f9c2`。
- OpenAPI から消えた `Sales\Sale::$memo` は、既存利用者との互換性のため残す。
  出典: `bd6f9c2`。

## 現在の状態

基底クラスでの初期化と上記 3 プロパティの nullable 宣言は現行コードにも残っており、判断は
有効である。ページネーションはこの一般則に委ねず、`Page::build()` と `Pagination` が欠損・
不正値を固有例外で扱う。出典: `ae36b5a`、`ead46f7`。

## 帰結

API が省略または `null` を返し得る項目の getter は、PHP の戻り値型まで一貫して nullable に
する。OpenAPI に根拠がない項目は、実レスポンスまたは互換性上の根拠なしに型を弱めない。
