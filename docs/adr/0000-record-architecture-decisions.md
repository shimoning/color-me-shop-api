# ADR 0000: アーキテクチャ上の意思決定を記録する

- 状態: 採用
- 決定日: 2026-09-11

## 文脈

設計上の判断理由をコードやコミットメッセージだけから追えず、過去の経緯を再調査するコストが
発生していた。また、`docs/TESTING_PLAN.md` は作業進捗簿として作成されたが、実装の進行に伴って
現状と乖離し、保守できなくなった。そのため、将来参照する設計判断を ADR 0001〜0004 へ整理した
うえで同ファイルを削除した。出典: `7b598a9`、`b96d4b8`。

一方、ADR 自体を後から更新してよいかという運用ルールは明文化されていなかった。本 PR では
ADR 0001 の決定内容を現行実装に合わせて書き換えかけ、当時の記録へ戻して、新しい判断を
ADR 0005 として追加する形へ是正した。出典: `027286d`、`c34a5ce`。

## 判断

- ADR には、アーキテクチャ上または設計上の意思決定を記録する。実装の詳細、作業手順、進捗、
  テスト件数のスナップショットは記録しない。それらは git 履歴、テスト、CI 設定を正本とする。
- ステータスは `提案中` → `採用` → `非推奨` / `置き換え済み` の順に遷移させる。採用済みの ADR
  には、既存 ADR と同じく `採用` と表記する。
- 一度採用した ADR の決定内容は書き換えない。決定が変わった場合は新しい ADR を作成し、旧 ADR
  には「ADR XXXX により更新」または「ADR XXXX により置き換え」の参照のみを追記する。
- 採用後も、誤字、リンク切れ、事実誤認は決定内容を変えない範囲で訂正してよい。ステータスの変更と、
  更新または置き換え先への参照の追記も認める。
- ファイル名は、4 桁の連番と英小文字のケバブケースをハイフンでつないだ
  `NNNN-title-in-kebab-case.md` とする。
- 各 ADR の必須セクションは「文脈」「判断」「代替案と却下理由」「帰結」「関連」とする。
- 各判断には、根拠を追跡できる出典コミット SHA を付記する。

## 代替案と却下理由

- `docs/adr/README.md` にインデックスと運用ルールを作る案は、ADR の件数が少ない現時点では
  時期尚早であるため採用しない。件数が増え、一覧性が必要になった時点で再検討する。
- CONTRIBUTING や README に運用ルールを書く案は、ADR 自体が意思決定の記録形式であり、ADR を
  使うという判断も ADR で記録する方が一貫しているため採用しない。

## 帰結

今後、採用済みの設計判断を変更する際は、既存 ADR の決定内容を書き換えず、新しい ADR を追加する。
旧 ADR には新しい ADR への参照だけを追記し、判断の変遷を履歴として残す。

本 PR で、ADR 0001 の記録を保ったまま、変更後のアクセストークン検証の判断を ADR 0005 として
追加した対応は、この方式の適用例である。出典: `c34a5ce`。
